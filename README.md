# BRNV Currency Converter · Android

Нативний безкоштовний конвертер валют на Kotlin і Jetpack Compose. Без акаунтів,
підписок і платних функцій. Android-версія [brnvconverter.com](https://brnvconverter.com).

## Перший етап

- Два початкові рядки EUR/USD; можна додати всі доступні валюти, без ліміту у чотири.
- Редагування суми в будь-якому рядку перераховує решту. Крапка й кома підтримуються.
- Вибір, пошук за кодом, англійською/українською назвою та псевдонімами сайту.
- 77 фіатних валют із каталогу BRNV, прапорці й локалізовані символи валют Android.
- Перестановка та видалення через меню рядка; мінімум два рядки, без дублікатів.
- Обране, порядок валют і остання сума зберігаються на пристрої.
- Реальні курси ExchangeRate-API; кеш доступний після перезапуску без інтернету.
- Дата курсів, явна позначка збережених даних, повідомлення про помилки.
- Світла/темна тема за системою, палітра BRNV, англійська та українська локалізації.

На першому запуску потрібне завантаження курсів. Застосунок не підставляє вигадані
курси, якщо немає ні мережі, ні кешу. Валюти, для яких провайдер не надав курс,
залишаються в каталозі сайту й отримують явне повідомлення про відсутній курс.

## Структура

```text
app/src/main/java/com/brnv/currencyconverter/
  BrnvApplication.kt            — спільні залежності на рівні процесу
  MainActivity.kt               — точка входу
  domain/                      — каталог, BigDecimal-розрахунки, стан конвертера
                                 та контракт/політика репозиторію курсів
  data/                        — HTTPS, JSON, атомарний файловий кеш, налаштування
  ui/converter/                — Compose UI, ViewModel і StateFlow
  ui/theme/                    — світла/темна палітра BRNV
```

UI → ViewModel → ExchangeRateRepository → RateDataSource + RateCache.
Провайдера можна замінити через `RateDataSource`. Формула перерахунку:
`amount × targetRate / sourceRate`; усі курси мають спільну базу USD.
Проміжні обчислення не округлюються до точності відображення.

Дискові та мережеві операції виконуються на `Dispatchers.IO`. Репозиторій
серіалізує конкурентні запити, спершу віддає кеш, враховує час наступного
оновлення API, обмежує ручні оновлення одним запитом на годину та повтори після
помилки — одним на хвилину в поточному процесі. Запити не виконуються при
редагуванні суми, виборі або перестановці валют. Фонових завдань поки немає.

Кеш записується через `AtomicFile` у внутрішнє сховище. Невеликий набір
налаштувань зберігається через `SharedPreferences` поза головним потоком,
з об’єднанням послідовних змін протягом 300 мс. Резервне копіювання вимкнене.

## Збірка

Поточні налаштування початкового проєкту збережено: minSdk 28 (Android 9),
compileSdk/targetSdk 37, AGP 9.4.1, Gradle 9.6.0, Kotlin Compose plugin 2.2.10,
Compose BOM 2026.02.01. Lifecycle узгоджено на 2.9.4 для ViewModel і
`collectAsStateWithLifecycle`. AndroidX JUnit 1.3.0 та Espresso 3.7.0 замінюють
застарілі тестові залежності для сумісності з поточним Android. Kotlin вбудований у AGP 9; окремий Android Kotlin
plugin не потрібен. Gradle daemon використовує JDK 25, Java source/target — 11.

Потрібні JDK 25, Android SDK Platform 37 та `local.properties` з локальним шляхом
до SDK. У терміналі Windows з налаштованим `JAVA_HOME`:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
.\gradlew.bat :app:connectedDebugAndroidTest
```

Друга команда потребує запущеного емулятора або підключеного Android-пристрою.
APK: `app/build/outputs/apk/debug/app-debug.apk`.

Тести використовують власні фікстури; не залежать від поточного курсу чи мережі.
Перевіряють конвертацію, редагування, кеш, конкурентні запити, помилки,
JSON/дискове збереження й основні Compose-сценарії.

Перевірено для першого етапу: debug APK збирається, 16 модульних і 5 Android-тестів
проходять на емуляторі API 37. Android Lint: 0 помилок, 7 попереджень про доступні
новіші залежності. Додатково перевірено реальне завантаження курсів, повторний
запуск із вимкненою мережею, світлий екран та темний екран зі шрифтом 150%.
MinSdk 28 і фізичний пристрій ще потребують окремої перевірки.

3. Мінімальні Settings, Contact, About і Support після перевірки способу підтримки.
4. Власна launcher-іконка, остаточна типографіка, розширена перевірка доступності.
5. Перевірка на minSdk 28, фізичних пристроях та підготовка Google Play release.

Деталі дослідження та рішення щодо віджетів: [docs/architecture.md](docs/architecture.md).
Це перший робочий етап, ще не готовий реліз Google Play.
