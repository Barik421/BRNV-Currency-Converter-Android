# Підготовка релізу 1.0

## Збірка
Пакет `com.brnv.currencyconverter`, versionCode `1`, versionName `1.0`, minSdk `28`, targetSdk `37`. Release використовує оптимізацію R8. Для наступних завантажень у Play Console збільшувати versionCode.

```powershell
$env:JAVA_HOME = 'D:\program\android studio\jbr'
./scripts/Build-Release.ps1
```

Скрипт вимагає локальний підпис, запускає модульні тести, release Lint, збирає APK/AAB і виводить їхні SHA-256. Перед поданням також потрібні перевірки встановленої release-збірки, віджетів і звіт Play Console.

Для окремого запущеного емулятора: `./scripts/Test-ReleaseStartup.ps1`. Він перевіряє, що підписана release-версія не падає після холодного старту. Одного `am start` зі статусом `ok` недостатньо: процес може впасти одразу після нього.

- Для Google Play: `app/build/outputs/bundle/release/app-release.aab`.
- Для перевірки поза магазином: `app/build/outputs/apk/release/app-release.apk`.
- Мапа оптимізації: `app/build/outputs/mapping/release/mapping.txt`; її копія також входить у AAB.

Не встановлювати release APK поверх debug APK: їхні підписи різні. Видалення debug-застосунку видалить його локальні налаштування. Для перевірки краще окремий емулятор. Після Play App Signing підпис доставленого магазином застосунку також може відрізнятися від локального APK.

## Ключ підпису
Локальний upload key створено 17 жовтня 2026, alias `brnv-upload`, RSA 3072. Це ключ для завантаження AAB; Play App Signing налаштовується окремо у Console.

Секретні файли, виключені з Git:
- `.local/signing/brnv-upload.jks` — ключ;
- `signing.properties` — шлях, alias та паролі.

Доступ до них обмежений поточним Windows-користувачем. Не надсилати їх у чат і не класти у публічний репозиторій. Власнику слід зробити захищену резервну копію обох файлів, наприклад у зашифрованому сховищі. Резервна копія на незалежному носії ще не зроблена.

`scripts/New-UploadKey.ps1` призначений лише для першого налаштування. Він генерує випадковий пароль, не друкує його та відмовляється перезаписувати існуючі ключі. Не створювати новий ключ для кожної збірки.

SHA-256 сертифіката (не секрет): `7fa3a76215840c33ce36a787646f935cda730718af403bbaff28c192887898a5`.

На іншому комп’ютері дозволено збирати проєкт без signing.properties для перевірки коду, але такий release буде непідписаним. Скрипт Build-Release навмисно не допускає цього.

## Питання, які треба закрити перед публікацією
1. Створити й підтвердити акаунт Play Console, налаштувати Play App Signing та тестовий трек.
2. Погодити контактні дані й політику зі `store/privacy-draft-uk.md`, опублікувати її на сайті та додати робоче посилання в застосунок.
3. Узгодити атрибуцію ExchangeRate-API: чинний безключовий endpoint прямо вимагає посилання на джерело. Воно було вилучене з інтерфейсу за попереднім побажанням власника. Потрібне повернення ненав’язливого посилання або інша стратегія даних до публікації; самостійно відновлювати прибраний елемент у цьому аудиті не стали.
4. Перевірити актуальні умови CoinGecko та вміст донат-сторінки. Донат-посилання не вважається перевіреним на відповідність Play лише тому, що воно відкриває браузер.
5. Завершити runtime-перевірки Android 9 та віджетів саме підписаного release у реальному лаунчері; зняти актуальні скриншоти. Холодний старт і онлайн/офлайн-конвертація release на API 37 вже перевірені.
6. Погодити Data safety, цільову аудиторію та інші анкети за фактичною поведінкою застосунку й сервісів.

Ці пункти є підготовкою релізу, а не новими функціями. Наявність підписаного AAB не означає готовності до публічного випуску.

## Перевірки 17 жовтня 2026
- 25 модульних тестів — успішно.
- 16 Android-тестів на API 37, системний масштаб шрифту 130% — успішно; включно з темами, мовами, конвертацією, кешем і віджетами.
- Виправлено занадто дрібні цифри компактного подвійного віджета на масштабі 130%; збережено перевірки відсутності обрізання та проміжку між результатами.
- Під час окремої перевірки release виявлено IllegalAccessError у Kotlin/AndroidX Startup. Вилучено експериментальний packageScope з конфігурації R8, щоб оптимізувати застосунок узгоджено.
- Додано точкове правило `src/release/keepRules/work-database.keep`: Room створює WorkDatabase_Impl через рефлексію, тому його публічний конструктор необхідно зберігати. Без нього повністю оптимізований release падав ще до відкриття головного екрана.
- Фінальний підписаний release успішно пройшов холодний старт без записів про падіння. Онлайн: 100 EUR → 112.15 USD за отриманим курсом; після вимкнення Wi-Fi і мобільної мережі та перезапуску налаштування збережені, показано «Using saved rates», перерахунок 1000 EUR → 1121.52 USD працює. Мережу емулятора відновлено.
- `testDebugUnitTest`, `lintRelease`, `assembleRelease`, `bundleRelease` — успішно. Lint: 0 помилок, 23 попередження; вони не замінюють перевірку Play Console. Android-тести виконувалися на debug, окрема перевірка запуску та конвертації — на підписаному release.
- Підписи APK/AAB перевірено; APK проходить zipalign з 16-КБ вирівнюванням. APK: 4 349 442 байти; AAB: 5 692 557 байтів.
- SHA-256 APK: `F44F6C50630F89770916714C6E203060D44FE70DC3B230B61BFAFBB194DF9673`.
- SHA-256 AAB: `0D331C4C48ADC0EF1C580FCA60C4B6ABDE0F9EADC0C5DCE7A2C781A05A51DD8D`.
- Емулятор скопійовано в ігноровану `.local/avd` на D, оскільки на C недостатньо місця. Вихідний AVD не змінювався.
- Android 9 / API 28 ще не перевірено на виконанні: у поточному SDK встановлено лише образ API 37. Це відкрита перевірка, а не підтверджена сумісність за результатом тесту.
