## Початковий стан

Локальна папка містила стандартний проєкт Android Studio: один модуль `app`,
`MainActivity` з Hello Android, фіолетова Material-тема та два шаблонні тести.
Каталогу `.git` не було. Після повторної перевірки origin став доступним і не
містив гілок; локальна гілка створена як `main`.

Початкові залежності: Core KTX 1.10.1, Activity Compose 1.8.0,
Lifecycle Runtime KTX 2.6.1, Material 3/Compose через BOM 2026.02.01,
JUnit 4.13.2, AndroidX JUnit 1.1.5, Espresso 3.5.1, Compose UI Test/Tooling.
У першому етапі змінено Lifecycle на 2.9.4 та додано його Runtime Compose
і ViewModel KTX. AndroidX JUnit оновлено до 1.3.0, Espresso до 3.7.0:
початкова версія Espresso падала на API 37 через видалений метод InputManager.
Нових DI/HTTP/navigation-фреймворків поки немає.

## Дані

Сайт використовує `https://open.er-api.com/v6/latest/{base}` для фіатних валют.
[Документація провайдера](https://www.exchangerate-api.com/docs/free) дозволяє
кешування й конвертацію без API-ключа, вимагає attribution, повідомляє про
щоденне оновлення та rate limiting. Посилання на джерело додано на екран.

Android завантажує один USD-знімок замість запиту на кожну пару. Час курсу
береться з `time_last_update_unix`, термін оновлення — з `time_next_update_unix`.
UI окремо показує використання збережених даних та невдалу спробу оновлення;
мережева помилка не називається достеменною відсутністю інтернету.

Обчислювальна модель не залежить від Activity або Compose. Немає випадкових
курсів, автоматичного підставляння 1:1 чи платних серверних залежностей.

## Віджети — запланований наступний етап

Перевірено офіційні настанови:

- [Glance та RemoteViews](https://developer.android.com/develop/ui/compose/glance/create-app-widget)
- [Конфігурація екземплярів](https://developer.android.com/develop/ui/compose/glance/configuration)
- [Стан і оновлення](https://developer.android.com/develop/ui/compose/glance/glance-app-widget)

Glance підходить для minSdk 28. Його компоненти відрізняються від Compose UI
та підпорядковані обмеженням AppWidget/RemoteViews. Поле редагування суми
не слід імітувати на домашньому екрані. Натискання суми відкриватиме компактну
Activity з конкретним widget ID; збереження оновлюватиме відповідний віджет.

Сховище конфігурацій матиме окремий ключ для кожного `appWidgetId` і версію
схеми: вид віджета, список валют, базова валюта/сума, appearance. Список валют
замість жорстко заданої пари залишає шлях до майбутнього мультивалютного віджета.
Це майбутня реалізація; невикористані класи й залежності зараз не додаються.

Configuration Activity починає з RESULT_CANCELED, записує налаштування,
явно оновлює Glance й повертає RESULT_OK з ID. Видалення віджета очищає лише
його налаштування. Reconfiguration підтримуватиметься на сумісних launcher-ах.

Фонове оновлення через унікальний WorkManager job потрібне тільки за наявності
віджетів. Усі екземпляри використовуватимуть спільний кеш. Щоденному фіатному
API не потрібні запити кожні 15 хвилин. Мережеву роботу не можна виконувати
безпосередньо в receiver; після worker оновлюються відповідні Glance-віджети.

## Оновлення 12 жовтня

Додано окремий CoinGeckoRateDataSource та крипто-кеш зі строком оновлення 5 хвилин.
Ціна USD за монету інвертується до монет за USD. Для стейблкоїнів також використовується
фактична ціна; відсутні або некоректні ціни не підміняються. Дата крипто-знімка —
найстаріша дата серед отриманих котирувань. У UI статуси двох провайдерів розділено.
Дати зберігаються для роботи кешу, але на запит власника не показуються на екрані.

Публічний endpoint сайту перевірено без ключа. Поточна
[документація CoinGecko](https://docs.coingecko.com/demo/reference/simple-price)
описує Demo API з ключем; анонімний доступ не є гарантією для production.
За зміни умов слід замінити джерело через RateDataSource, не вбудовувати секрет
у APK. Кеш та незалежна робота фіатного API вже передбачені.

Для мов використано [AppCompatDelegate](https://developer.android.com/guide/topics/resources/app-languages)
та AppCompatActivity. Дев’ять повних наборів рядків UI, системна локалізація назв
фіатних валют для додаткових мов, ручний вибір або наслідування пристрою.
Іконка — нативний VectorDrawable із двома стрілками обміну, симетричними відносно
повороту на 180°. Adaptive та monochrome варіанти використовують ту саму геометрію.
Генеративне зображення не потрібне.

[Google Play In-App Review](https://developer.android.com/guide/playcore/in-app-review)
використовує локальну політику достатнього користування й 90-денну паузу.
Немає запитань про задоволеність, стимулів або відбору позитивних оцінок.
Кнопка веде до Play Store, автоматичний запит — до офіційного API.

## Перший етап віджетів — 14 жовтня

RateWidget використовує стабільний Glance 1.2.0. Кожен appWidgetId має окремий
JSON-запис із версією схеми, типом, списком валют, сумою та темою. Конфігурація
перевіряє належність ID нашому receiver, починає з RESULT_CANCELED, зберігає дані,
оновлює віджет і тільки тоді повертає RESULT_OK. Видалення очищає лише відповідний запис.

Для першого етапу використовується системний updatePeriodMillis = 6 годин;
provideGlance завантажує дані через спільні репозиторії у worker Glance.
Окремий нескінченний фоновий сервіс чи власний періодичний WorkManager job не потрібні.
Це не віджет біржових котирувань у реальному часі: він показує дату та стан кешу.
Віджет курсу підтримує одну або дві незалежні пари з окремими сумами та
спільним перемикачем прапорів для цього екземпляра. Схема налаштувань v2 додає
showFlags і необов’язкову second; v1 читається з вимкненими прапорами й однією парою.
Спільні репозиторії завантажують курси для обох пар без окремого запиту на кожний рядок.
Швидкий віджет і його Activity вилучено: користувач відмовився від окремого вікна
та цифрової панелі. Звичайне системне поле введення всередині RemoteViews недоступне.

Фіатні результати віджетів округлюються до сотих; криптовалюти зберігають точність
спільного форматера. Свіжий кеш не показує попередження: воно потрібне лише після
помилки оновлення чи закінчення строку актуальності. Дата курсу залишається видимою,
крім найкомпактнішого розміру. Для picker додано previewLayout з підтримкою теми
та PNG previewImage для старіших Android. Демонстраційні числа у прев’ю статичні.

Після полірування віджет завжди використовує тему пристрою; поле theme у старій
схемі збережено для сумісності, але воно не керує відображенням. Налаштування
містять лише пару й суму, кнопку збереження та доступний хрестик закриття.
SizeMode.Exact і LocalSize змінюють типографіку та відступи відповідно до обох
розмірів віджета. Довгі значення додатково обмежуються шириною тексту.
Стрілка — векторна іконка, вирівняна по центру рядка, а не символ шрифту.
Кожна конверсія отримує рівну частину висоти віджета. Розмір цифр розраховується
за доступною висотою цього рядка та обмежується шириною значення; код цільової
валюти показується лише в заголовку, звільняючи місце для великих цифр.
Підбір шрифту вимірює SP у реальних пікселях, залишає запас для відступів
лаунчера та обмежує максимальний розмір відповідно до ширини. Дата має окремий
нижній відступ. Регресійний тест перевіряє відсутність ellipsis у числі для
110×110, 140×140, 180×180 і 320×180 dp та відступ дати від нижнього краю.
Підхід відповідає [Glance sizing](https://developer.android.com/develop/ui/compose/glance/build-ui).

Сторінку donate.html перевірено: добровільна підтримка без доступу до додаткових
функцій; застосунок лише відкриває офіційну сторінку в браузері. Перед публікацією
потрібно повторно звірити її поточний вміст з умовами Google Play щодо добровільних внесків.
